### 3.2 私信主人（唯一写操作）

规则与流程：

```
主人存在 → 内容校验（非空 / ≤300 字 / 无链接）
        → 配额（日 10 / 同一人 3 / 间隔 5 分钟）
        → Chrome 9222 可用 → 已登录 → 不是给自己发
        → 打开 message.bilibili.com/#/whisper/mid<主人 UID>
        → 输入 → 点发送 → 输入框清空视为成功
        → 截图 runtime/dm-last.png → 追加 audit.jsonl
```

接口：

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/dm/owner` | 返回是否可用 + 当前主人（UI 用它决定是否显示面板） |
| POST | `/api/dm/owner` | `{ content }`，发送给主人 |

CLI：

```bash
node src/cli.mjs dm --dry-run "只输入不发送"
node src/cli.mjs dm "发给主人的内容"
```

### 3.3 主人与 @ 规则

- `src/policy.mjs`：`ensureOwnerMention(text, owner)`
  - 没有 @ → 自动补 `@<owner.name>`
  - 只有主人 @ → 通过
  - 出现其他 @ → 拒绝并返回名字
- CLI：`node src/cli.mjs comment-check "草稿"`
- 控制器/未来的评论执行器必须先调用它；**目前还没有评论执行器**。

### 3.4 DSH 插件

| 文件 | 作用 |
|---|---|
| `plugin/host.mjs` | 在 DSH web server 上注册 `/bili-duty` 前缀，交给同一个 `createApp` |
| `plugin/client.js` | 注册 `settings.section`（B 站），内嵌 `/bili-duty/?embed=1` |
| `cordis.patch.yml` | `insert` 一个 `id: bili-duty` 的 bundle entry |
| `package.json` | `main` / `exports` / `dsh.bundle` / `dsh.client` |

- 安装方式：DSH → 插件 → 添加插件 → 本地目录（`link:`），**重启 DSH 生效**。
- 宿主代码在启动时加载；更新插件代码后必须重启，面板/接口才会更新。
- 旧宿主下 UI 会探测 `GET /api/dm/owner`，404 时隐藏私信面板并提示重启，避免出现坏按钮。

## 6. 下一步（建议顺序）

### 第 1 步：阶段 1 只读链路（优先）

产出：

- `skills/bili-playbook`（登录检查、限速、aria snapshot、失败即停）；
- 只读工具链：搜索 → 打开 3–5 个视频 → 分段滚动读评论 → 总结；
- 写入 `runtime/memory/watched.jsonl` 与当日笔记；
- 控制台加“只读自检”入口（可选）。

验收：连续 3 天跑通，零写操作；记录成功率、耗时、token；页面改版时能明确报错而不是静默失败。

### 第 2 步：guard + 审核器 dry-run

- `src/guard.mjs`：白名单/长度/频率/配额/敏感词/链接，确定性；
- `src/reviewer.mjs`：固定提示词 + JSON schema + 超时 → 失败一律 `human`；
- 离线样例集：广告、引战、政治、超长、注入指令；
- 控制台“待审”页原型。

验收：样例判定符合预期；审核器不可被主 Agent 影响；审计字段完整。

### 第 3 步：L2 评论执行器 + 人工审批

- 评论输入/发送/复核（Shadow DOM）；
- 发送前强制 `ensureOwnerMention`；
- 规则 → AI → 人工 → 一次性 token → 执行；
- 审计写 `action=comment`。

验收：第一条真实评论由人工在待审页点通过；@ 只为 owner；发送后核验可见。

### 第 4 步：L1 + 调度/急停

- 点赞/投币/收藏；
- 谷时窗口、间隔抖动、每日配额、`STOP`；
- L1 审计与每日复盘。

### 第 5 步：L3 / AUTO

- 动态日 1 + 人工点发布；
- AUTO 前置条件与降级，最后再评估。

## 7. 已知问题与风险

| 问题 | 影响 | 处理 |
|---|---|---|
| 运行中的插件宿主代码不会热更新 | 改 host 后必须重启 DSH | UI 已做可用性探测；文档提示重启 |
| DSH 同时启用 `@perrylink/dsh-github` 与 bili-duty 时启动失败（用户反馈“依赖重复”） | github 插件被禁用 | `package.json` 无 github 依赖；待拿启动报错定位（可能是 client inject / bundle 层冲突） |
| Chrome 未运行时私信直接失败 | 发送前必须确保 9222 可用 | 未来可在发送前自动拉起 Chrome，或状态页一键启动 |
| 评论/审核未实现 | 还不能发评论，也不能验证三层审核 | 阶段 2/3 |
| B 站 DOM 使用哈希类名 | 改版可能失效 | 优先 aria/角色；失败即停、截图 |
| 私信非互关限制 | 未验证 | 第一个真实联系人验证（当前主人已互关） |
| 仓库公开 | 真实 UID/Cookie 泄露风险 | 白名单/审计/chrome-profile 全部 gitignore；文档不含真实 UID |
