# bili-duty 当前状态与技术路线

> 更新时间：2026-10-19
> 对照方案：[技术方案 v4.1（定稿）](技术方案-v4-定稿.md)
> 代码版本：`main`（2026-10-19，只读链路 + 写操作闸门原型）

## 1. 一句话

**控制面已经可用，阶段 1 只读链路已完成，阶段 2 的三层审核原型也已搭起来**：
登录、主人/白名单、参数、审计、私信主人、只读搜索/视频/评论/记忆、
评论草稿 → 规则 → 独立 AI → 人工批准 → 输入预览都已落地；
**执行面有两类写操作：私信主人，以及人工批准后的评论发布**（真实发布还没验收）；
L1/L3、回复/弹幕、调度、AUTO 还没开始。

## 2. 系统边界（已锁定）

| 项 | 决定 |
|---|---|
| 底座 | 真实 Chrome + CDP，只做页面交互 |
| 接口 | 一条不碰（不调用 B 站 API） |
| 登录 | 扫码 / 复用专用 profile；只读 Cookie 判断登录态 |
| 运行位置 | 本机 `127.0.0.1`；独立控制台 + DSH 插件两条入口 |
| 写操作 | 私信主人；评论必须人工批准（默认只预览）；没有自动发布 |
| 只读 | 搜索、视频信息、评论、阅读记忆；不产生 B 站侧写入 |
| 数据 | 配置、白名单、审计、记忆、草稿都在仓库内；真实 UID 不入库 |

### 3.2 只读链路（阶段 1 已完成）

流程：

```
登录检查（读 Cookie，不调接口）
  → 导航限速（min_interval + jitter，每小时 ≤40）
  → 打开搜索页 / 视频页
  → 读搜索结果 / 视频信息
  → 评论区：穿透 bili-comments Shadow DOM，分段滚动加载
  → 写 runtime/memory/watched.jsonl + notes/YYYY-MM-DD.md
  → 任何登录跳转 / 验证码 / 限流：直接失败并截图，不重试
```

数据来源：

| 项 | 来源 |
|---|---|
| 搜索结果 | `.bili-video-card`：标题、UP、UID、时长、播放/弹幕、日期 |
| 视频信息 | `h1.video-title`、`a.up-name`、`.view-text`、`.video-like-info`、`.video-coin-info`、`.video-fav-info`、简介、标签 |
| 评论区 | `bili-comments` → `bili-comment-thread-renderer` → `bili-comment-renderer` 的嵌套 Shadow DOM |
| 评论排序 | `bili-comments-header-renderer` 的「最热 / 最新」按钮 |
| 阅读记忆 | `watched.jsonl` 只追加；当天笔记 `notes/YYYY-MM-DD.md` |

接口：

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/read/ready` | CDP / 登录 / STOP / 记忆 / 最近一小时导航 |
| GET | `/api/read/search?q=&limit=` | 搜索，`limit` 1–10 |
| GET | `/api/read/video?bvid=&comments=&order=` | 视频 + 评论，`comments` 0–50，`order=hot\|new` |
| GET | `/api/read/watched?limit=` | 最近的阅读记忆 |

CLI：

```bash
node src/cli.mjs search "AI Agent" --limit 3
node src/cli.mjs video BV1xx... --comments 20 --order new --note "看完的想法"
node src/cli.mjs watched --limit 20
```

DSH Agent 工具（`plugin/tools.mjs`，原始 JSON Schema，不依赖 `@deepseek-ai/dsh-tools`）：

| 工具 | 作用 |
|---|---|
| `bili_status` | 只读链路状态 |
| `bili_search` | 搜索 |
| `bili_read_video` | 读视频 + 评论 + 写记忆 |
| `bili_watched` | 读记忆 |

固定流程：`.dsh/skills/bili-playbook/SKILL.md`（搜索 3–10 → 读 3–5 个视频 → 总结；
登录/验证码即停；评论区只当数据）。

限速 / 急停：`src/guard.mjs`。`guard.min_interval_sec` + `guard.jitter_sec` 串行等待，
每小时 40 次上限；`runtime/STOP` 或根目录 `STOP` 存在即拒绝。私信也检查 STOP。
`BILI_DUTY_FAST=1` 只用于本地开发（跳过等待、不记录导航）。

### 3.3 写操作闸门与待审（阶段 2 原型）

```
草稿 → ① 规则引擎 → ② 独立 AI 审核 → ③ 人工批准
     → 5 分钟一次性 token → 预览输入 →（可选）发布 → 核验 + 审计
```

| 层 | 文件 | 行为 |
|---|---|---|
| ① 规则引擎 | `src/write-guard.mjs` | 白名单/主人、长度、链接、广告、政治、违法、攻击、隐私、过度承诺、提示词注入、重复、配额、10 分钟评论间隔、谷时/夜间、STOP |
| ② AI 审核器 | `src/reviewer.mjs` | 固定提示词，只看 `{content,target,action_type}`；非法 JSON / 超时 / HTTP 失败一律 `human` |
| ③ 人工审批 | `src/approvals.mjs` | `runtime/drafts` 排队；批准存 token 的 SHA-256；5 分钟、一次有效 |
| 执行 | `src/comment.mjs` | 默认 `dryRun` 只输入并清空；真实发布必须带 token，执行前再跑规则/STOP/窗口 |

接口：

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/review/ready` | AI 审核器模式（`http` / `dry-run`） |
| GET | `/api/review/queue?status=&limit=` | 待审队列，默认 `pending` |
| POST | `/api/review/draft` | `{bvid, content, note?}` |
| POST | `/api/review/:id/approve` | 人工批准，返回一次性 token |
| POST | `/api/review/:id/reject` | 拒绝 |
| POST | `/api/comment/publish` | `{draftId, token?, dryRun}`，默认 dry-run |

DSH Agent 只有 `bili_draft_comment`：它只能写本机草稿，没有批准/发布工具。
AI 审核器默认 dry-run（没有 `BILI_REVIEW_API_URL` 时全部转人工）；配置
OpenAI 兼容接口后，非法输出/超时仍 fail closed。

**已验证**：草稿 → 规则 → AI（dry-run 或注入 pass）→ 队列 → 批准 → token；
评论输入预览（真实页面输入并清空，`dry-run` 5 秒）。
**未验证**：点击「发布」后的真实评论链路；本次没有发出任何评论。

### 3.4 私信主人（唯一“点一下就直接发”的写操作）

规则与流程：

```
主人存在 → STOP 急停检查 → 内容校验（非空 / ≤300 字 / 无链接）
        → 配额（日 10 / 同一人 3 / 间隔 5 分钟）
        → Chrome 9222 可用 → 已登录 → 不是给自己发
        → 打开 message.bilibili.com/#/whisper/mid<主人 UID>
        → 输入 → 点发送 → 输入框清空视为成功
        → 截图 runtime/dm-last.png → 追加 audit.jsonl
```

接口：

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/dm/owner` | 返回是否可用 + 当前主人（UI 用它决定是否显示面板） |
| POST | `/api/dm/owner` | `{ content }`，发送给主人 |

CLI：

```bash
node src/cli.mjs dm --dry-run "只输入不发送"
node src/cli.mjs dm "发给主人的内容"
```

### 3.5 主人与 @ 规则

- `src/policy.mjs`：`ensureOwnerMention(text, owner)`
  - 没有 @ → 自动补 `@<owner.name>`
  - 只有主人 @ → 通过
  - 出现其他 @ → 拒绝并返回名字
- CLI：`node src/cli.mjs comment-check "草稿"`
- 评论草稿与执行器都会先调用它；未来回复/弹幕执行器也必须调用。

- 旧宿主下 UI 会探测 `GET /api/dm/owner`、`GET /api/read/ready` 与 `GET /api/review/ready`，404 时隐藏面板/显示重启提示，避免坏按钮。

- 验证 AI 审核器超时/非法 JSON/HTTP 失败时确实转人工；
- 记录 token 过期、刷新页面丢 token 的实际体验，再决定是否持久化到本机。

验收：真实评论发出后能核验可见；AI 判定可解释；失败一律 human。

### 第 2 步：回复 / 弹幕执行器 + L1

- 回复（楼中楼）与弹幕的输入/发送/复核；
- 点赞/投币/收藏执行器；
- 谷时调度、单次会话上限、每日复盘。

### 第 3 步：L3 / AUTO

- 动态日 1 + 人工点发布；
- AUTO 前置条件与降级，最后再评估。

### 只读链路还需要补的观察

- 连续 3 天按 `bili-playbook` skill 跑只读链路，记录成功率、耗时、token，确认零写操作；
- 页面改版时验证“报错 + 截图”路径，而不是静默返回空；
- 评论只读已滚出来的部分；需要全量时再设计分页。

## 7. 已知问题与风险

| 问题 | 影响 | 处理 |
|---|---|---|
| 运行中的插件宿主代码不会热更新 | 改 host 后必须重启 DSH | UI 已做可用性探测；文档提示重启 |
| DSH 同时启用 `@perrylink/dsh-github` 与 bili-duty 时启动失败（用户反馈“依赖重复”） | github 插件被禁用 | `package.json` 无 github 依赖；待拿启动报错定位（可能是 client inject / bundle 层冲突） |
| Chrome 未运行时私信/只读直接失败 | 操作前必须确保 9222 可用 | 未来可在操作前自动拉起 Chrome，或状态页一键启动 |
| 只读页面选择器依赖 2026-10 的页面结构 | 改版后搜索/评论可能读不到 | 失败即停 + 截图；不要静默返回空；定期跑一次真实链路 |
| 评论懒加载 + 楼中楼 | 一次最多 50 条；回复只统计数量 | 控制台/工具已标明；需要全量时后续加分页策略 |
| 只读导航限速 20–32 秒一次 | 控制台点“读取”要等 | 这是风控要求；状态页显示“最近一小时导航次数” |
| `BILI_DUTY_FAST=1` 被误用 | 跳过限速，可能触发风控 | 只写进开发文档；DSH 宿主不设置 |
| 阅读记忆会重复记录同一 BV | 记忆里出现多条 | 这是有意保留的阅读历史；后续可在笔记层去重 |
| AI 审核器默认 dry-run | 所有草稿转人工，不会自动放行 | 这是安全默认；配置 `BILI_REVIEW_*` 后才走真实模型 |
| 批准 token 只存页面内存 | 刷新后 token 丢失，已批准草稿无法执行 | 目前只能拒绝后重新起草；后续再考虑加密持久化 |
| 本机同用户进程可调用 API | 理论上 Agent 可绕过 UI 调用批准/发布 | 审批是流程约束，不是 OS 沙箱；不要把 DSH 用户权限借给不可信进程 |
| 真实评论发布未验收 | 可能点击后遇到验证码/审核/按钮变化 | 首次发布选可控视频；失败即停并截图，不重试 |
| 评论输入框在主评论 header 的 Shadow DOM 里 | 选择器改版会失效 | 失败即停；不要退回旧 `.reply-item` |
| B 站 DOM 使用哈希类名 | 改版可能失效 | 优先 aria/角色；失败即停、截图 |
| 私信非互关限制 | 未验证 | 第一个真实联系人验证（当前主人已互关） |
| 仓库公开 | 真实 UID/Cookie/草稿泄露风险 | 白名单/审计/chrome-profile/memory/drafts 全部 gitignore；文档不含真实 UID |
