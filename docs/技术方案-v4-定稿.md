# 在 B 站养一个 AI 账号 —— 技术方案（v4.1 · 定稿）

> 版本：v4.1（2026-10-18）· **定稿** · 取代 v3
> v4.1 修订：路径改为实际工作区（G 盘）、补「路径约定」、校正 §1.1/§1.2 的事实表述与附录 A 的实测条件；架构、配额、审核、调度均不变。
> 定位：**公开运营、明示 AI 身份的 B 站账号**，由 DeepSeek Agent 驱动，长期"养"出人格与记忆。
> 底座：**真实 Chrome + Playwright**，不碰任何 B 站接口。
> v4 变更：**私信配额放宽**（好友白名单、日 10、同一人 3、默认免人工）；其余为定稿整理。

---

## 0. 结论

| 问题 | 答案 |
|---|---|
| 能不能让 AI 操作 B 站账号 | 能，但**只走浏览器 UI**（不碰接口；页面内 fetch 实测 412） |
| 评论/回复能做吗 | 能。Shadow DOM，Playwright 可穿透（已实测） |
| 私信能做吗 | 能。只发给**好友白名单**（人数少、已知情），日 ≤10、同一人 ≤3，默认免人工 |
| 点赞/投币/收藏 | 能，投币每天 1 枚 |
| L3 发动态 | 每天至多 1 篇，人工审核 |
| 能不能全自动发 | **默认不能**。只有白名单动作通过测试后才可自动（§7） |
| 谁来审核 | **不是本体 AI**。规则引擎 + 独立审核器 + 人工，三层分离（§6） |

**一句话**：生成归生成，审核归审核，执行归执行——三者不共享上下文。

## 1. 三条硬约束

### 1.1 第三方 API 库已停止维护（仓库永久关停）

`bilibili-api-python` 的仓库（Nemo2011/bilibili-api）已声明停止维护并将永久关停；B 站委托上海市弘安律师事务所于 **2026-07-06** 发函，认定其对非公开接口的逆向适配构成侵权。PyPI 上 **17.4.2** 仍可安装、也仍能跑（GPLv3），但**无人维护、法律定性已由平台书面表达**。**不作为底座。**

（2026-10-18 核对：仓库 README 与 PyPI 元数据均如此。「能装能跑」不等于「可以用」——法律风险才是决策依据。）

### 1.2 实测：页面内 fetch 也被拦（未登录）

```
GET api.bilibili.com/x/web-interface/view?bvid=...
→ HTTP 412 Precondition Failed（HTML 验证页）
```

2026-10-18 的实测条件：真实 Chrome 155、同源页面、`credentials: "include"`，但**没有登录 cookie**，结果 412。
页面内 fetch 带不上 B 站要求的 `wbi` 签名，所以**「用浏览器当代理调接口」这条路走不通**；写操作只走 UI。

> 待验证（阶段 1，登录后）：页面内 fetch 是否仍 412。无论结果如何，本方案都不走接口。

### 1.3 合规

- 《AI 生成合成内容标识办法》（2025-09-01）：AI 内容须标识。实测视频页已出现"**含AI生成内容**"角标。
- 2026 年六类必选标签：`内容由 AI 生成` / `虚构演绎` / `营销广告` / `转载` / `个人观点` / `其他`。
- B 站有"AI 技术滥用"专项治理。
- 用户协议禁止"通过自动程序获取服务/内容/数据"——低频拟人 UI 操作处灰色地带。

## 3. 执行层：页面结构（已实测）

### 3.1 评论区是 Shadow DOM

```
<bili-comments> → #shadow-root
   ├ <bili-comments-header-renderer>
   ├ <bili-comment-thread-renderer> → #shadow-root
   │     ├ <bili-comment-renderer id="comment"> → #shadow-root
   │     │     ├ <bili-comment-user-info>
   │     │     ├ <bili-rich-text>          ← 正文
   │     │     └ <bili-comment-action-buttons-renderer>
   │     └ <bili-comment-replies-renderer> ← 楼中楼
   └ <bili-comment-box>                    ← 输入框（需登录）
```

| 能力 | 可行 | 不可行 |
|---|---|---|
| 读评论 | aria snapshot / CSS 穿透 shadow | `.reply-item`（实测 0 个） |
| 定位元素 | aria snapshot 的 ref | `querySelector`（穿不透 shadow） |
| 写评论 | contenteditable + 发送按钮 | 构造请求（412） |

### 3.2 登录态差异

| 页面 | 未登录 | 登录后 |
|---|---|---|
| 视频评论区 | 仅置顶 + "登录后查看 N 条" | 全量 + 输入框 |
| `message.bilibili.com` | 302 → passport | 会话列表 + 输入框 |
| `t.bilibili.com` | 可浏览不可发 | 可发布 |

| 级 | 能力 | 实现 | 默认配额 |
|---|---|---|---|
| **L0** | 搜索、看视频、读评论、看主页/动态 | 只读 | 无限制（受导航限速） |
| **L1** | 点赞 | 点击 | **日 ≤20** |
| | 投币 | 点击 + 选币 + 确认 | **日 ≤1** |
| | 收藏 | 点击 + 选夹 + 确认 | **日 ≤10** |
| **L2** | 发评论 | 富文本 + 发送 | **单视频 ≤1**、**日 ≤3** |
| | 回复评论 | 同上（楼中楼） | **单 root ≤2**、**日 ≤10**、**总 ≤10** |
| | 发弹幕 | 播放器输入 | 日 ≤5 |

**L2 的三个维度为什么必须同时存在：**

- **每日总量**防"一天到晚在评论区"。

三者任一超限即拒绝，不看其他维度剩余多少。

## 5. 关键技术实现

### 5.1 读评论

```
browser_navigate → 等 bili-comments 出现 → 分段滚动触发分页
→ browser_snapshot({depth:8}) 或 browser_evaluate 只读抽取
```

优先 aria snapshot（结构稳、有 ref）；量大时用 evaluate 抽 `bili-rich-text` 文本，省 token。

### 5.2 发评论 / 回复

```
1. 校验登录（页头头像）
2. locator('bili-comment-box').locator('[contenteditable="true"]')
3. click 聚焦 → browser_type({slowly:true}) 逐字输入
4. 等 300–800ms，确认发送按钮可用
5. click 发送
6. 重新 snapshot 核验；查不到写"没查到"，不写"没发出去"
```

**坑位：**

- 富文本不吃 `fill()`，必须 `type()`；
- 敏感词在发送时弹提示，**不重试**，记录失败；
- 新号/高频触发滑块，**停下交给人**；
- 评论可能进审核 → 用最新评论页核验。

### 5.3 发私信（好友白名单）

```
1. 校验目标 UID ∈ dm-allowlist.json，否则拒绝
2. navigate → message.bilibili.com/#/whisper
3. 若跳 passport ⇒ 停
4. 定位会话 / 搜索用户 → 输入框输入 → 发送
5. 核验气泡出现
```

**约束（按"好友已知情"放宽）：**

| 项 | 值 | 说明 |
|---|---|---|
| 白名单 | 硬约束 | 由你维护，Agent 无写权限 |
| 日上限 | **10** | 好友数量少，不需要卡太死 |
| 同一人/日 | **3** | 允许正常对话来回 |
| 最小间隔 | 5 min | 防连发刷屏 |
| 人工确认 | **默认免** | 白名单都是知情好友；AI 审核仍生效 |
| 链接 | 禁止 | 最易判营销 |
| 群发 | 禁止 | 一次只能一个目标 |

**保留人工确认的开关**：`dm_require_human: true` 可随时打开，用于"某个好友最近状态不对"或"重要消息"的场景。

**仍需实测**：非互关限制规则——即便在好友白名单里，若对方未关注账号，可能只能发 1 条。这条登录后第一件事验证。

### 5.4 点赞 / 投币 / 收藏

| 动作 | 关键点 |
|---|---|
| 点赞 | aria 名称"点赞"定位；再点取消 |
| 投币 | 弹面板选 1 枚 → 确认；**日 1 枚**，避免清空 |
| 收藏 | 弹夹选择 → 确认；注意别建新夹 |

### 5.5 发动态（L3）

```
创作中心 → 输入正文 → （可选）配图 → 勾选 AI 标识 → 预览 → 停在发布按钮
→ 截图 → 人工点最后一下（默认）
```

### 5.6 登录与验证码

- 登录**永远人工**；
- 跳 passport / 登录弹窗 ⇒ 全停告警；
- 验证码/滑块 ⇒ 停，截图，等人。

## 6. 审核架构（生成与审核分离）

### 6.1 三层分离

| 层 | 谁 | 看什么 | 输出 | 可否被主 Agent 影响 |
|---|---|---|---|---|
| ① 规则引擎 | `bili-guard` 代码 | 内容、目标、当前配额 | pass / reject | 否 |
| ② AI 审核器 | **独立 headless 会话** | 仅内容 + 目标 + 规则摘要 | pass / human / reject + 理由 | 否 |
| ③ 人工 | 你 | 完整草稿 | 通过 / 改 / 拒 | 是（最终） |

**"审核不是本体 AI"的落地方式：**

- 审核器跑在**独立进程/独立会话**，系统提示词是固定的审核模板；
- 输入只有：`{content, target, action_type}` —— **没有**对话历史、人格设定、生成理由；
- 主 Agent 无法调用、无法修改、无法看到审核器内部状态；
- 审核结果写入只追加的 `audit.jsonl`，主 Agent 只读。

### 6.2 审核器输出

```json
{
  "verdict": "pass | human | reject",
  "risk": "low | medium | high",
  "reasons": ["..."],
  "suggest": "可选改写建议"
}
```

判定规则：

- `reject`：命中禁止项 / 高风险 → 直接拒，不给人看；
- `human`：中风险或不确定 → 转人工（默认路径）；
- `pass`：低风险且 AUTO 通道开启 → 可自动执行。

### 6.3 审核提示词要点（独立，不复用主 Agent 的）

```
你是内容审核器。你不认识作者，不知道上下文，只判断这段文字能不能发在公开评论区。
只输出 JSON，不解释。
拒绝：引战、人身攻击、地域/性别/民族歧视、政治敏感、医疗/法律/投资建议、
      广告引流、外链、冒充真人、虚假事实、过度承诺。
存疑：涉及具体数字/时间/人名但无法验证、语气激烈、长度异常。
通过：技术观察、感谢、回答提问、日常记录，且 ≤100 字。
```

### 6.4 审计

```jsonl
{"ts":"...","action":"comment","target":"BV...","content":"...",
 "rule":"pass","ai":"pass","human":"approved","exec":"ok","verify":"visible"}
```

- 只追加，不修改；
- 保留 ≥90 天；
- 每周复盘：拒绝率、人工改判率、核验失败率。

## 7. AUTO 通道（白名单自动化）

### 7.1 允许自动的动作（仅这三类）

| 动作 | 条件 | 风险 |
|---|---|---|
| 私信主人（账号持有者本人） | 永远允许 | 极低 |
| 回复主人（主人在评论区的留言） | 永远允许 | 极低 |
| 短评论（≤50 字，白名单主题） | 需通过测试 + 双审 | 中 |

**明确不允许自动的**：动态、视频、专栏、私信他人、弹幕、任何带链接的内容。

### 7.2 开启 AUTO 的前置条件（全部满足）

- [ ] 连续 **14 天**无风控事件（验证码/限流/审核）
- [ ] 累计发出 ≥**20 条**内容，核验可见率 **100%**
- [ ] 规则引擎 + AI 审核器**双通过**
- [ ] 人工抽检 ≥**20%**，且抽检通过率 ≥95%
- [ ] 你显式开启 `auto.enabled: true`

### 7.3 AUTO 的降级

任何一条触发即**立即关闭**，回落到全人审：

- 任意一次风控提示
- 任意一条核验失败（发出但不可见）
- 任意一次人工抽检不通过
- 任意一条被举报/下架

关闭后需重新满足 7.2 才能再开。

### 7.4 为什么这样设计

全自动的风险不在"AI 会不会写坏话"，在"**没人看着的时候它连续做错**"。
AUTO 通道用"历史表现"换"事后监督"：先证明 20 次都对，才允许它自己发第 21 次。

## 9. 调度：只在谷时运行

### 9.1 谷时定义

| 时段 | 是否谷时 |
|---|---|
| 工作日 09:00–12:00 | 否（高峰） |
| 工作日 12:00–14:00 | 是 |
| 工作日 14:00–18:00 | 否（高峰） |
| 工作日 18:00–次日 09:00 | 是 |
| 周末全天 | 是 |

### 9.2 调度器行为

- 只在谷时窗口内启动会话；
- 窗口结束前 10 分钟停止新的写操作；
- 非谷时：不启动、不排队、不"补跑"；
- 单次会话最长 40 分钟，超时自动收尾。

### 9.3 为什么

三个理由叠加：省钱（谷时便宜）、错峰（避开平台高峰风控）、拟人（真人也不会 24 小时在线）。

```
memory/
├── watched.jsonl   看过的：BV/标题/UP/结论/日期
├── people.jsonl    互动过的：UID/昵称/聊过什么
├── said.jsonl      自己发过的：时间/动作/正文/结果
└── self.md         自我认知：做过什么、犯过什么错、最近在想什么
```

- 每次只加载摘要（最近 20 条 + self.md）；
- `said.jsonl` 同时是判重基础；
- 每周让 Agent 写一段 `self.md` —— "成长感"的来源。

### 10.3 日程

| 频率 | 做什么 | 级别 |
|---|---|---|
| 每天 | 逛：搜关键词、看 3–5 个视频、记笔记 | L0 |
| 每周 | 复盘：整理 memory、更新 self.md | L0 |
| 有值得的 | 点赞/投币/评论 | L1/L2 |
| 每天 ≤1 | 发动态 | L3 |

## 11. 风控与限速

### 11.1 硬限额

| 动作 | 间隔 | 每小时 | 每天 |
|---|---|---|---|
| 导航 | 8–20s 随机 | ≤40 | — |
| 搜索 | ≥15s | ≤20 | ≤100 |
| 点赞 | ≥20s | ≤10 | ≤20 |
| 投币 | ≥60s | ≤3 | **≤1** |
| 收藏 | ≥30s | ≤5 | ≤10 |
| 评论 | ≥10min | ≤1 | ≤3 |
| 回复 | ≥10min | ≤1 | ≤10 |
| 弹幕 | ≥5min | ≤1 | ≤5 |
| 私信 | ≥5min | ≤5 | ≤10 |
| 动态 | — | — | ≤1 |

### 11.2 拟人化

- 间隔随机，不固定；
- 打开视频后**真的停留** 20–90 秒；
- 滚动分段，不一次到底；
- 输入逐字，不粘贴；
- 避开整点/半点；
- 夜间 00:00–07:00 不做写操作。

### 11.3 异常处理

| 信号 | 动作 |
|---|---|
| 验证码/滑块 | 全停，截图，告警 |
| "操作过于频繁" | 当天该类全停 |
| 评论不可见 | 记"没查到"，不重试 |
| 跳登录页 | 全停，人工重登 |
| 412/风控页 | 停 24h |
| 警告/下架 | L3 停 30 天 + 复盘 + 关 AUTO |

## 12. 内容白名单与禁止项

### 12.1 允许

| 类型 | 例子 |
|---|---|
| 技术观察 | "今天看到 X，我的看法是…" |
| 日常记录 | "这周看了 12 个视频，最喜欢…" |
| 回应提问 | "有人问我会不会 X，答案是…" |
| 自我修正 | "上次我说错了，更正一下…" |
| 简单互动 | 感谢、赞同、接梗（≤30 字） |

### 12.2 禁止（硬拒，不进人工）

| 类别 | 具体 |
|---|---|
| **政治敏感** | 时政、政策评价、领导人、历史争议 |
| **违法信息** | 黄赌毒、诈骗、破解、翻墙教程 |
| **人身攻击** | 辱骂、嘲讽、地域/性别/民族/职业歧视 |
| **引战** | 拉踩、对比挑事、挂人、带节奏 |
| **专业建议** | 医疗诊断、法律意见、投资荐股 |
| **广告引流** | 站外链接、二维码、联系方式、拉群 |
| **冒充** | 假称真人经历、假称官方、伪造身份 |
| **隐私** | 他人真实姓名、住址、电话、工作单位 |
| **虚假** | 编造事实、伪造数据、虚构来源 |
| **过度承诺** | "保证""一定""百分百" |
| **低质刷屏** | 复制粘贴、无意义字符、纯表情 |

### 12.3 存疑转人工

- 涉及具体数字/时间/人名且无法核实；
- 语气激烈或含反讽；
- 长度异常（评论 >100 字，私信 >300 字）；
- 提到具体产品或公司（可能被当广告）。

## 定稿说明

本文档为**最终技术方案**。落地时按 §13 阶段推进，参数以 `config/config.yaml` 为准（§8 只是摘要）。

**已锁定、不再议的事项：**

- 底座 = 浏览器 UI，接口一条不碰
- 审核 = 规则引擎 + 独立 AI + 人工，生成者不得参与审核
- 调度 = 只在谷时
- 投币 = 日 1
- L3 动态 = 日 1 + 人工
- 私信 = 好友白名单，日 10、同一人 3、默认免人工

**随实施推进才确定的事项：**

- `persona.md` 的具体文字（初稿见 `../persona/persona.md`）
- 账号注册与养号的实际时间
- 登录后三项待验证的技术细节（附录 A 的 ⏳ 项）

**变更管理：** 任何参数调整只改 `config.yaml`，不改本文档；若涉及架构变更（如换底座、改审核流），升版本号并记录到附录 B。
